# Prediction Question Configuration Platform

## Storage Model

Fixture question configuration is stored on draft fixtures as
`predictionQuestionConfig`.

The configuration contains:

- `schemaVersion`
- optional standard question configs in canonical order
- custom question configs in deterministic display order

Old draft fixtures without `predictionQuestionConfig` derive the current
canonical defaults from `defaultRuleset`. Old published fixtures continue to use
their stored `rulesetSnapshot` and are not retrospectively mutated.

## Domain Module

Shared source:

- `imports/shared/predictionQuestions/types.ts`
- `imports/shared/predictionQuestions/configuration.ts`

The module owns:

- `MAX_CUSTOM_QUESTIONS_PER_FIXTURE` (`2`)
- supported custom answer types (`number`, `choice`)
- optional standard question IDs
- permanent core question IDs
- text limits
- validation and normalization
- default derivation
- projection from standard question config to a scoring ruleset snapshot

The implementation reuses the existing scoring domain concepts:

- `custom-numeric`
- `custom-categorical`
- `customAnswers`

CCPP-008 stores richer draft custom configuration for future player/settlement
milestones, but custom-question fixtures are blocked from publication until the
player sequence can answer them.

## IDs And Ordering

Custom question IDs and choice option IDs are stable lower-case identifiers.
They are generated by the admin UI and validated server-side. IDs are not
derived from prompt or option label text.

The server never trusts client order fields. Custom questions are stored in the
submitted array order with normalized one-based `order` values.

## Validation

Server validation is authoritative and rejects:

- unknown fields
- unsupported optional standard IDs
- attempts to configure permanent core questions through the optional standard
  API
- unsupported custom answer types
- more than two custom questions
- missing prompts
- missing counting definitions
- invalid numeric min/max values
- maximum lower than minimum
- invalid deductions
- fewer than two choice options
- empty choice labels
- duplicate normalized choice labels
- duplicate question or option IDs

Optional standard incorrect deductions use the existing scoring ruleset
constraint: finite positive safe integers. Custom Number and Choice deductions
accept finite non-negative safe integers for draft configuration.

## Methods And Publications

Admin method:

- `fixtures.admin.saveQuestionConfig`

Input:

- `fixtureId`
- `expectedRevision`
- `config`

The method requires the existing platform-admin authorization path. It validates
and normalizes the full configuration, writes only to draft, not-cancelled
fixtures, and increments the fixture revision atomically.

Admin publication:

- `fixtures.admin.list`

This admin-only publication now includes `predictionQuestionConfig`.

Public fixture publications do not include draft question configuration. The
player prediction fixture context continues to publish only the published
fixture context and `rulesetSnapshot`.

## Revision And Concurrency

Question configuration uses the existing fixture `revision` as its concurrency
token.

The admin editor captures a fixture revision when opened. Reactive fixture
changes do not silently advance the captured revision or replace unsaved
configuration. A stale save returns `fixture-conflict` and leaves unsaved values
in the editor. `Reload` explicitly replaces local values with the latest visible
fixture configuration and captures the latest revision.

Successful question-config saves increment the fixture revision and return the
new revision to the editor.

## Draft, Published, Cancelled

Draft fixtures:

- question configuration is editable
- optional standard questions can be toggled
- custom questions can be added, edited, removed, and reordered

Published fixtures:

- question configuration is read-only
- optional standard enabled states and deductions are frozen in the stored
  `rulesetSnapshot`
- repeated publication does not regenerate the snapshot

Cancelled fixtures:

- question configuration is read-only

## Snapshot Integration

Publishing a standard-only draft builds the fixture ruleset snapshot from the
stored question configuration:

- permanent core questions remain from the authoritative default ruleset
- optional standard enabled states are applied
- optional standard incorrect deductions are applied
- disabled optional standard questions remain in the snapshot as disabled
  question definitions

The player standard sequence already consumes active built-in questions from the
stored snapshot, so disabled optional standard questions remain ignored by the
player flow.

## Temporary Custom Publish Gate

If a draft fixture contains one or more custom questions, `fixtures.admin.publish`
rejects with:

`Custom questions are configured for this fixture, but custom-question player predictions are not enabled yet.`

The fixture remains draft, its custom question configuration remains saved, and
no ruleset snapshot is written.

## Future Extension Points

Future player integration can append custom questions after built-in configured
prediction questions and before Review unless a later product decision changes
the ordering model.

Future settlement/result work should add official answers, pending/settled/void
state transitions, and scoring against the stored custom question identities and
counting definitions. CCPP-008 does not implement those workflows.
